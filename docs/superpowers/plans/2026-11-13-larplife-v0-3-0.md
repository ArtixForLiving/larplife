# Larplife v0.3.0 (Full Rust) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade `larplife` from v0.2.0 to v0.3.0 (Full Rust) by introducing instant startup detection, zero-debounce for empty state, official `larplife` badge RPC support, 3-layer Application ID system with 24-hour disk-cached detectable apps & scoring resolver, multi-host local image upload with PE/Win32 icon extraction, and non-blocking asynchronous Settings GUI.

**Architecture:** Maintain strict separation between the background daemon (pure Win32/Named Pipe, zero HTTP, $< 10\text{ MB}$ RAM, $\sim 0\%$ CPU) and the standalone GUI process (`--settings`). All network operations (`ureq`), image encoding (`png`), and disk caching run exclusively within worker threads inside the GUI process, communicating with `egui` via `mpsc::channel`.

**Tech Stack:** Rust (Edition 2024), `windows` crate 0.62, `eframe`/`egui` 0.31, `discord-rich-presence` 1.1, `serde`/`serde_json`, `ureq` (lightweight sync HTTP client), `png` (lightweight in-memory encoder).

**Spec:** [docs/PRD_v0.3.0.md](file:///d:/Larplife/docs/PRD_v0.3.0.md) (Revisi Final v0.3.0)

---

## Global Constraints
- Target OS: Windows 10 / 11 64-bit.
- RAM usage in background daemon must remain $< 10\text{ MB}$ (Actual baseline: $2.1\text{--}5.8\text{ MB}$).
- Zero async runtime (no `tokio`) to prevent binary bloat and high memory footprint.
- All external HTTP calls must be isolated to `--settings` and executed off the UI rendering thread.
- Backward compatibility: existing `config.json` without new v0.3.0 fields must deserialize safely via `#[serde(default)]`.
- All automated unit tests must be hermetic (mock trait responses, no live internet requests required).
- All 40 existing unit tests must continue to pass 100%.

## Review Focus
1. **Network Failure / Offline Mode:** If no internet connection exists, GUI must not hang or crash; app resolver gracefully falls back to local cache or Layer 2 (larplife fallback), displaying an inline warning without modal popups.
2. **Corrupted Disk Cache:** If `%LOCALAPPDATA%\larplife\detectable_cache.json` is partially written or invalid JSON, parsing must discard it safely and fall back without `panic!`.
3. **PE Icon Extraction Alpha Channel:** When converting Win32 icon bitmaps to PNG, ensure `BGRA` $\to$ `RGBA` color order conversion so transparent backgrounds do not turn into solid black boxes.
4. **Rapid Process Switching (Alt-Tab):** Zero-debounce must only apply when transitioning from `None` (empty) to registered app. Switching between registered apps A $\to$ B must preserve 2-cycle debounce (~4s) to avoid Discord rate limiting.
5. **String Boundary Safety:** Discord details, state, and badge tooltip must enforce `floor_char_boundary(120)` and minimum 2-char padding.
